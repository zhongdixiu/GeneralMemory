# 接口总览

本页供对接时快速定位入口与权限。逐接口的字段、响应和调用示例见 [完整接口说明](完整接口说明.md)；专题运行步骤仍见各既有说明。精确的请求/响应约束以 `src/memory_cmic/api_schemas.py` 和 `src/memory_cmic/api.py` 为准。服务启动后，FastAPI 还提供 `/docs` 和 `/openapi.json`，适合查看当前运行版本的自动生成 schema。

## 统一约定

- 所有业务接口使用 `Authorization: Bearer <token>`。租户和调用 Agent 由凭证决定，请求正文不传 `tenant_id`。
- Add 的 `source_system` 必须在凭证 `allowed_source_systems` 中。Search/Profile 需要具有业务 Agent 来源资格；管理能力由独立开关控制。
- `user_id` 由可信后端提供，本服务尚未核验终端登录用户与该 ID 的绑定，不能直接面向不可信终端开放。
- 可以发送 `X-Request-ID` 便于链路定位；响应会回传。错误响应为 `{"error":{"code":"...","message":"..."}}`。
- POST/PUT 请求体在中间件处限制为 2 MiB。具体字段长度与格式由请求 schema 校验；不要用显式 `null` 代替省略可选字段。
- 返回 `202` 的任务接口表示已接收或已入队，不代表模型处理、向量维护或画像重建已完成。

## 最小对接流程

### 写入一条对话

```text
POST /api/v1/memories:add
  → 202 + task_id
GET /api/v1/tasks/{task_id}
  → pending / succeeded / partial / failed / cancelled
```

内部 `processing` 状态在这个接口中显示为 `pending`。请求至少包含 `source_system`、`user_id`、`session_id` 和非空 `messages`。每条消息有 `message_id`、`role`、`content`；历史消息放 `history_messages`。重复重试使用同一幂等键和同一内容；内容变化应使用新的键和消息 ID。完整示例见 [ADD 接口运行说明](ADD接口运行说明.md#提交消息)。

### 读取与修改

```text
POST /api/v1/memories:search  → 获得 memory ID 和正文
GET  /api/v1/profiles         → 获得已重建的画像陈述
PUT  /api/v1/memories/{id}    → 返回替代事实的新 ID
DELETE /api/v1/memories/{id}  → 逻辑删除
```

Search 默认不调用大模型判定场景适用性；若任务需要模型判断正文条件，显式设置 `use_model=true`。PUT 只接受当前有效的个人事实；推断不能原地编辑。修改/删除后的向量物理维护是异步的，但读取端会过滤不再有效的旧对象。详见 [Search 与 Profile](Search与Profile接口运行说明.md) 和 [修改与删除](记忆修改与删除接口运行说明.md)。

## 接口变更时同步检查

1. `api_schemas.py` 的字段和校验、`api.py` 的路由与错误映射。
2. 涉及 Add 时，`ingest.py` 的请求指纹、持久化来源字段和 Worker 输入读取。
3. 涉及返回可见性时，`retrieval.py`、`profile.py`、`evidence.py` 的条件。
4. 对应专题运行说明、此页接口清单、专项 API 测试。
