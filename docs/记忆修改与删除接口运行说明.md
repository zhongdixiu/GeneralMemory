# 记忆修改与删除接口运行说明

日期：2026-10-16。

## 已确认的入口与范围

- 自然语言修改、纠正继续走 `POST /api/v1/memories:add`，沿用现有事实抽取和替代判断。
- 自然语言删除由业务 Agent 理解请求，调用 Search 定位 ID，必要时向用户澄清，再调用 DELETE。本次不向 Add 添加 DELETE 动作。
- 管理侧或获授权业务后端通过 DELETE 删除个人 fact/inference，通过 PUT 修改当前有效的个人 fact 正文。Agent 自身记忆、组织记忆、画像不在接口范围内。
- 修改创建新事实并返回新 ID，旧事实保留正文并转为 invalidated；新事实的 supersedes_id 指向旧 ID。inference 不直接编辑，可删除或通过 Add 澄清。
- 删除为逻辑删除：memory_item 原行保留并标记 deleted，不清空来源原文、不迁移到 History 库。审计复用 memory_audit_log。

## 部署与权限

部署前停止 API/Worker 写入，使用项目环境执行 `alembic upgrade head`，升级至 `0011_memory_deleted`，再启动新版进程。迁移仅扩展 memory_item 的状态约束，不改写存量记忆；存在 deleted 数据时 downgrade 会失败并回滚，不自动恢复或改写这些记录。

过渡阶段只配置业务 Agent 凭证，在同一条凭证上按需设置三个开关；不要求另配治理/管理 token。三个开关均默认 false，未来由独立授权控制面接管。示例：

```json
{
  "token": "replace-with-a-long-random-token",
  "tenant_id": "tenant_example",
  "caller_agent_id": "business_backend",
  "allowed_source_systems": ["email_agent"],
  "can_manage_memories": true,
  "can_manage_governance": true,
  "can_read_audit_content": true
}
```

can_manage_memories 控制 PUT/DELETE；can_manage_governance 控制整理、治理策略和画像重建；can_read_audit_content 控制审计正文读取，可独立开启，不要求同时开放治理。治理开关仍允许查询审计元信息，正文须另开内容开关。allowed_source_systems 保留业务来源写入限制及当前 Search/Profile 的接入资格判定；开关不扩大租户范围。

请求使用 `Authorization: Bearer <configured-token>`。租户和真实调用身份来自凭证；user_id 由受信任接入后端提供，接口同时检查租户、个人记忆归属和指定用户。公司终端用户身份验证仍未接入，不能将此权限授予不可信终端客户端。

## DELETE

`DELETE /api/v1/memories/{memory_id}?user_id=user1`

- user_id 必填，非空白，最长 128 字符。
- expected_version 可选，正整数；目标尚未删除且版本不一致时返回 409。
- reason 可选，最长 512 字符，作为审计原因。
- active/disputed/invalidated/expired 均可删除。deleted 是普通更新、治理恢复不能重新启用的状态。
- 重复删除返回当前 deleted 记录，不递增版本、不重复写审计或提交清理任务；重复请求可携带首次删除前的 expected_version。

```json
{
  "id": "mem_example",
  "version": 2,
  "status": "deleted",
  "supersedes_id": null
}
```

HTTP 200 表示逻辑删除事务已提交，不表示向量物理清理、画像重建全部完成。

删除同事务完成目标状态/版本变更、DELETE 审计、出边失效、下游充分性检查及后台任务入队。依赖目标的推断/画像若失去全部完整证据组，立即停止输出；仍有其他独立完整证据组的保留。向量立即标记 stale，交由已有 vector_delete 任务物理删除。

来源消息和目标的入边保留以便追溯。删除某条记忆不自动删除同一来源产生的其他事实，也不递归删除其替代链中的其他记录。已有来源重新抽取或新的输入仍可能生成新的相似条目；本次不提供永久语义屏蔽或原文物理清除。

## PUT

`PUT /api/v1/memories/{memory_id}`

```json
{
  "user_id": "user1",
  "content": "用户要求周报先提供风险说明。",
  "expected_version": 1,
  "reason": "用户修正要求"
}
```

- user_id、content 必填，不能全为空白；content 最长 8000 字符。
- expected_version 可选，必须为 JSON 正整数；用于防止基于旧版本修改。省略时在用户事务锁和目标行锁内操作当前记录。
- reason 可选，最长 512 字符。不接受 status、范围、TTL、tenant_id 等额外字段。
- 只允许当前 active、已生效且未到期的个人 fact。不恢复 deleted、invalidated、expired、disputed，不直接改写 inference。
- 完全相同的正文为无操作，返回原 ID，不生成来源、替代条目或新审计。
- 正文替换保持原业务/项目范围、生效时间、到期时间和保留分类。调用方应保留必要适用条件；修改范围、时间或多条独立事实应通过 Add 表达，不在本接口增加模型解析。

```json
{
  "id": "mem_replacement",
  "version": 1,
  "status": "active",
  "supersedes_id": "mem_example"
}
```

调用方应使用返回的新 ID。旧 ID 已被替代，再次对其修改返回 409，不重复创建事实；本接口不新增 Idempotency-Key 协议。

更新同事务创建 source_type=manual、source_system=memory_management 的新来源和 supports 证据，不复用原文来证明新正文。来源及审计记录真实调用 Agent，不伪造终端用户身份。新事实继承适用范围，清除旧消息位置、治理决策和画像准入等处理元数据。原事实失效后，旧推断和画像按证据组规则立即退出使用，不自动把旧证据关联改绑到新事实。

向量生成使用已有 vector_upsert，旧向量使用 vector_delete，画像仍按现有合并等待规则重建。接口本身不调用模型，缺少模型凭证时仍可提交，Worker 需要有效 embedding 配置才能完成新向量；新向量完成前 Search 不返回新事实，旧事实也不会继续输出。

Search 的来源过滤跟随新依据：手工修改后的来源系统是 memory_management，来源 Agent 是本次编辑凭证的 caller_agent_id，不沿用原始 Agent。此手工来源可直接证明管理写入，不伪造 fact_extract 任务。省略来源过滤时保持同用户共享。

## 审计与错误

- DELETE：记录原状态/版本和 deleted 状态/版本、操作者、时间及原因，正文保留在原行，不再复制到删除事件。
- PUT：记录手工来源创建、旧事实失效、新事实创建，以及关联新旧 ID 和前后正文的 UPDATE 事件；事件共享 correlation_id。UPDATE 的 state_after 表示替代后的新事实，旧行自身的状态变化由 INVALIDATE 事件记录。
- 审计仍只追加；读取完整审计内容只需 can_read_audit_content=true，并传 include_details=true，不再要求治理开关。本次不保证补齐旧事件缺失的完整版本快照。

| 状态 | 错误码 | 含义 |
| --- | --- | --- |
| 401 | UNAUTHENTICATED | 凭证缺失或无效 |
| 403 | FORBIDDEN | 未授予 can_manage_memories |
| 404 | MEMORY_NOT_FOUND | 指定租户/用户下不存在可管理的个人记忆 |
| 409 | MEMORY_VERSION_CONFLICT | expected_version 与当前版本不一致 |
| 409 | MEMORY_NOT_EDITABLE | 目标不是当前可编辑的有效个人 fact |
| 422 | INVALID_MESSAGE | 请求字段或参数非法 |
