# 用户画像独立陈述优化方案与迁移说明

本次调整对应 migration `0005_atomic_profiles`，更新原 V1.0 中画像必须使用固定属性键的契约。事实、证据分组、来源失效传播和任务队列继续沿用现有机制。

> 2026-10-10 后续修订：`0007_profile_governance` 增加 `assertion_kind=explicit/inferred`。默认保留明确事实画像；显式开启后可消费通过递归证据及长期资格筛选的已有推断，并通过现有蒸馏记录准入结果。画像任务采用 2 分钟静默/30 分钟最长等待，同用户合并。以下内容为 `0005` 的历史迁移约定，当前行为及新增上线步骤见[治理优化方案](./记忆治理与推断画像统一优化方案.md)及[后台运行说明](./记忆治理后台运行说明.md)。

## 数据契约

- 自动画像的 `property_key` 为 NULL，`property_value` 为非空 string，每条表达一项能独立成立的用户信息。
- 支持明确、当前、长期适用的身份、职业、偏好、习惯和重复要求。项目角色、历史事实、临时任务和未经允许的推断不进入自动画像。
- 陈述必须保留业务条件、文档类型、否定和例外；不能把“周报简洁，风险部分详细”扩大成“所有输出简洁”。分类不是唯一性依据。
- 每条陈述独立关联 `profile_basis`。同一陈述、同一业务范围、同一生效及到期时间可以聚合多个独立事实依据，各自使用 OR 证据组。不同陈述不共享证据组。
- 实际业务需要精确读取单值属性时，仍可显式写入非空 `property_key`。非空 key 的唯一约束继续生效；自动生成器不定义新的固定属性。
- 原有 JSONB、value_type 字段兼容既有固定属性；数据库约束要求无 key 条目必须是非空字符串。新增按租户、用户过滤的 active 索引，供自动画像读取。

## 重建与读取

1. 从同租户、同用户的有效 fact 中选择有充分来源依据的当前内容，排除项目限定、历史、未来生效和已到期事实。
2. 模型返回 `memory_id`、`value`、`quote`，不返回 key。优先复用清晰事实的原文；只做形成完整陈述所需的最小改写。
3. 精确匹配内容、业务范围和有效时间。重复重建且依据版本保持有效时保留条目 ID；改写内容、范围、时间或依据变化时进行记录替换和审计。
4. 保留用户锁、任务租约和提交前水位复核；水位包含当前 eligible 事实 ID，防止模型调用期间事实过期后提交旧结果。
5. 读取同时检查画像状态、时间、业务范围，以及依据事实、原始来源的有效性。无 key 条目的依据业务范围必须与画像范围一致。

DUPLICATE、SUPERSEDE、DISPUTE 的语义判断由事实写入治理负责。画像不会按“同 key 不同文本”认定冲突，也不会自行采用最新文本覆盖。争议事实退出画像依据，明确纠正经事实治理后触发重建。

读取仍返回 `list[ProfileProperty]`。调用方应逐条使用 `property_value`，不能把自动画像转换为以 property_key 为键的字典。内部 `read_profiles()` 显式传入 business_domain 时仍按业务范围读取；2026-10-10 增加省略该参数时读取全部有效画像，并通过独立 REST 接口提供，见[Search 与 Profile 运行说明](./Search与Profile接口运行说明.md)。任务相关性依赖业务范围及陈述中的具体条件，模型消费时需要遵守这些条件。

## 存量迁移

迁移将以下旧自动画像键视为历史契约：

- 中文：姓名、职位、邮件回复偏好、输出要求。
- 英文：identity.preferred_name、pref.email.reply_style、pref.output.requirements。

`alembic upgrade head` 在一个事务内完成：

1. property_key 改为 nullable，单值唯一索引只覆盖非空 key；增加无 key 字符串约束和 active 用户索引。
2. 为有 active 旧画像的用户创建 `profile_rebuild` 任务，每个租户、用户一条。
3. 审计并使旧 active 画像及其证据边失效，保留原记录。其他既有固定属性不受此自动迁移规则影响。

旧输出要求列表不会直接拆分，因为旧列表的证据无法可靠映射到每个元素。新条目必须由剩余有效事实重新生成，无来源的旧画像不会恢复。

部署时先停止旧版本 Worker，再升级代码和数据库，随后启动新版本 profile Worker。迁移后、重建完成前，旧自动画像停止输出；事实检索继续使用有效事实。可按 task_type=profile_rebuild 查看重建任务的成功、失败和重试状态。

```bash
# 加载环境配置后执行
.venv/bin/alembic upgrade head
.venv/bin/python -m memory_cmic.worker --role profile
```

迁移版本进入系统任务幂等键 v3，避免旧版本已完成任务阻止首次新算法重建。失败重建按现有队列策略重试，不以历史画像内容作为生成依据。

## 回滚边界

存在无 key 条目时，downgrade 会因 NOT NULL 约束失败并回滚该事务，保留所有条目。需要先制定无 key 数据的转换方案；迁移不会自动删除它们或编造属性键。已执行的旧画像失效与历史审计不会通过 schema downgrade 自动恢复。

## 验收与限制

回归覆盖独立要求失效、兼容偏好、条件原文保留、不同范围与有效时间、多独立证据、重复重建、TTL、来源变化及调用期间到期，以及真实事实写入流程中的 ADD、SUPERSEDE、DISPUTE 到画像的联动。迁移测试检查旧记录及证据失效、用户重建合并、固定属性保留和回滚的数据保护。

这些测试使用确定性的模型替身，验证存储、队列和治理契约。模型能否正确判断长期价值、拆分独立内容、完整保留条件及识别事实矛盾，仍需要真实业务样本验证。精确 quote 校验证明引用来自依据，不能单独证明 value 的全部语义正确。
